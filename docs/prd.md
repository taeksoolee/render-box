# 1. 개요

## 1.1 목적

기획·운영자가 AI 도구 등으로 만든 HTML 파일을 올리면, 개발자·디자이너가 고유 URL로 바로 열어 실제 브라우저에서 동작을 확인할 수 있게 한다.

해결하는 문제:

1. HTML 파일을 메신저로 주고받고, 받은 사람이 내려받아 여는 번거로움
2. 같은 문서의 최신본이 무엇인지 알기 어려운 문제
3. 내부 데이터가 담긴 HTML을 외부 서비스(CodePen, GitHub Pages 등)에 올릴 수 없는 보안 제약

## 1.2 사용자

| 역할 | 대상 | 할 수 있는 것 |
| --- | --- | --- |
| EDITOR | 기획·운영자 | 등록, 수정(정보 수정·HTML 교체), 삭제, 열람 |
| VIEWER | 개발자·디자이너 | 열람 (목록, 상세, 렌더링, 소스 보기·다운로드) |
| 운영자 | 서버 관리자 | 접근 키 발급·회수·역할 변경 (웹 화면 없음) |

## 1.3 운영 방식

- Cloudflare 무료 플랜에서 운영한다. 서버 비용과 서버 관리가 없다.
- 무료 플랜의 처리 한도 안에서 동작하도록 설계했다. 그래서 큰 파일의 인코딩 판별·경고 검사 같은 작업은 브라우저에서 처리한다.
- 개발과 확인은 로컬에서 먼저 하고, Cloudflare 연결은 그 뒤에 한다.

## 1.4 핵심 사용 흐름

```
[기획자]  키로 로그인 → HTML 파일 드래그 → 제목·설명·링크 입력 → 저장 → URL 복사 → 메신저로 공유
[개발자]  URL 클릭 → (최초 1회 키 입력) → 새 창에서 렌더링 확인 → 필요하면 소스 다운로드·관련 링크 확인
[기획자]  수정본 생성 → 같은 문서에서 "HTML 교체" → 같은 URL로 최신본 제공
```

# 3. 로그인과 권한

## 3.1 접근 키

- ID/비밀번호 대신 **사람마다 다른 접근 키**로 로그인한다.
- 키는 운영자에게 받는다. 운영자는 사람마다 키를 발급하고, 필요하면 언제든 회수하거나 역할(EDITOR/VIEWER)을 바꿀 수 있다.
- 키를 한 번 입력하면 **30일간** 다시 입력하지 않아도 된다. 관리 화면과 렌더링 화면 모두에 적용된다.
- 브라우저 비밀번호 관리자에 저장할 수 있다.
- 키가 유출되면 운영자가 즉시 회수한다. 회수하면 그 키로 로그인된 모든 화면이 바로 로그아웃된다.

## 3.2 안전 안내

- **렌더링 화면은 키를 절대 묻지 않는다.** 렌더링 화면 안에서 키 입력을 요구하면 업로드된 HTML이 만든 가짜 화면이다.
- 이 안내를 로그인 화면과 목록 상단에 표시한다.

## 3.3 권한표

| 기능 | EDITOR | VIEWER | 비로그인 |
| --- | :---: | :---: | :---: |
| 목록·검색 | O | O | X |
| 상세 | O | O | X |
| 렌더링 | O | O | X |
| 소스 보기·다운로드 | O | O | X |
| URL 복사 | O | O | X |
| 등록 | O | X | X |
| 수정 (정보, HTML 교체) | O | X | X |
| 삭제 | O | X | X |
| 키·프로젝트·관리자 지정 | 운영자 (명령줄) | | |

렌더링 URL도 로그인한 사람만 볼 수 있다. URL을 받은 사람도 키가 있어야 한다.

**프로젝트:** 문서는 프로젝트(예: `tamna`) 하나에 속한다. 위 표의 역할은 그 프로젝트에서의 역할이고, 키는 프로젝트마다 다른 역할을 가질 수 있다. 속하지 않은 프로젝트의 문서는 목록에 보이지 않고, 주소를 알아도 열리지 않는다. 프로젝트를 만들고 키를 넣는 일은 운영자가 명령줄로 한다.

**관리자 키:** 모든 프로젝트(나중에 만든 것 포함)의 문서를 다른 키가 만든 것까지 보고 고치고 지울 수 있는 키다. 프로젝트에 따로 넣지 않아도 된다. 다만 키 발급, 프로젝트 만들기, 멤버 관리, 관리자 지정은 관리자도 할 수 없고 운영자가 명령줄로만 한다. 키가 새면 모든 문서가 열리므로 꼭 필요한 사람에게만 준다.

# 4. HTML 문서

## 4.1 문서 정보

| 항목 | 필수 | 규칙 |
| --- | :---: | --- |
| 제목 | O | 1~200자. 등록할 때 HTML의 `<title>` 또는 파일명으로 자동 채움 |
| 설명 | X | 최대 2,000자, 줄바꿈 유지 |
| 링크 | X | 최대 10개. 각 링크는 이름(선택, 최대 100자) + URL. URL이 빈 행은 저장하지 않는다 |
| HTML | O | 최대 10MB (무료 운영 환경의 처리 한도를 실측한 뒤 확정) |

자동으로 기록되는 정보: 문서 ID, 크기, 등록자·등록일, 수정자·수정일.

### 링크

기획서, Figma, Jira 티켓, 참고 사이트처럼 문서와 관련된 자료를 함께 남긴다.

- 이름을 비우면 URL의 사이트 주소(예: `www.figma.com`)로 표시한다.
- 입력한 순서대로 표시한다.
- `http://` 또는 `https://` 주소만 넣을 수 있다.
- 링크는 넣지 않아도 된다. 이름만 쓰고 주소를 비운 행도 오류 없이 빼고 저장한다.

## 4.2 등록

### 입력 방식

1. **파일**: HTML 파일(`.html`, `.htm`)을 끌어다 놓거나 선택
2. **붙여넣기**: HTML 코드를 텍스트 영역에 붙여넣기

파일을 선택하면 내용 대신 "파일명 · 크기"만 표시한다.

### 자동 처리

- **크기 확인**: 10MB를 넘으면 올리기 전에 바로 안내한다.
- **한글 인코딩**: EUC-KR로 저장된 옛날 HTML 파일은 자동으로 변환하고 "EUC-KR 파일을 UTF-8로 변환했습니다"를 안내한다.
- **제목 채우기**: 제목이 비어 있으면 HTML의 제목이나 파일명을 넣는다.

### 이미지 파일 연결 (선택)

HTML의 `<img src>`가 같은 폴더의 이미지 파일(예: `images/logo.png`)을 가리키면, 그 파일이 없어 이미지가 깨진다. 이 경우 이미지 파일을 함께 넣을 수 있게 한다.

이 도구는 기획 공유용이다. 이미지는 화면 구성을 전달하는 보조 자료이고, 디자인 시안·가이드는 피그마로 공유한다. 그래서 이미지가 없다고 저장을 막지 않는다.

- 경로마다 한 줄씩 표시하고, 줄마다 파일을 선택한다. 같은 경로가 여러 번 나오면 한 번만 받는다.
- [여러 파일 한 번에 선택]이나, HTML과 이미지를 함께 끌어다 놓으면 파일 이름이 같은 경로에 자동으로 연결한다.
- 저장할 때 선택한 이미지는 HTML 안에 포함(base64)하고, 선택하지 않은 이미지는 파일명이 적힌 회색 빈 상자로 바꾼다. 결과는 HTML 한 파일이며 10MB를 넘을 수 없다.
- 몇 개를 선택했고 몇 개가 빈 상자가 되는지 저장 전에 표시한다.
- `https://` 주소의 이미지, 이미 포함된 이미지(`data:`), 스크립트가 만드는 `<img>`는 대상이 아니다.

### 경고 (저장은 가능)

| 상황 | 경고 문구 |
| --- | --- |
| HTML이 같은 폴더의 스크립트·스타일 파일을 참조함 | 이 파일만 올라가므로 함께 있던 스크립트·스타일 파일은 동작하지 않습니다. HTML 안에 포함해서 다시 만들어 주세요 |
| `http://` 주소의 리소스를 씀 | 보안 연결(https)이 아닌 리소스는 브라우저가 차단합니다 |

### 저장 후

- 상세 화면으로 이동해 "저장했습니다"를 표시하고, [렌더링 URL 복사] 버튼을 강조한다.
- 입력 오류가 있으면 등록 화면에 오류를 표시한다. 입력한 제목·설명·링크·붙여넣은 내용은 유지된다. 파일은 브라우저 보안 정책상 다시 선택해야 한다.

### 내용 검사를 하지 않는 이유

올라온 HTML의 스크립트나 태그를 지우거나 막지 않는다. 그대로 실행해 보는 것이 이 서비스의 목적이다. 안전은 렌더링 화면을 관리 화면과 격리해서 확보한다 ([design.md](design.md) 5장).

## 4.3 목록

- 표시: 제목, 설명(한 줄로 줄임), 링크 개수, 크기, 수정자, 수정일, [새 창에서 보기]
- 정렬: 최근 수정순
- 검색: 제목 일부 또는 문서 ID 앞부분. 입력하면 바로 결과가 갱신된다.
- 한 페이지에 20개

## 4.4 상세

- 표시: 제목, 설명, 링크 목록, 문서 ID, 크기, 등록자·등록일, 수정자·수정일
- 버튼:
  - **새 창에서 보기**
  - **렌더링 URL 복사**
  - **소스 보기**: HTML 코드를 새 창에서 텍스트로 표시
  - **소스 다운로드**
  - **수정**, **삭제** (EDITOR만)

## 4.5 수정

- **문서 정보**(제목, 설명, 링크)와 **HTML 교체**를 한 화면에서 한다.
- HTML 교체 칸을 비워 두면 기존 HTML이 그대로 유지된다. 정보만 고칠 때 HTML을 다시 올릴 필요가 없다.
- HTML을 교체해도 **렌더링 URL은 바뀌지 않는다.** 이미 공유한 링크로 최신본을 볼 수 있다.
- 두 사람이 같은 문서를 동시에 수정하면 나중에 저장한 사람에게 "다른 사람이 먼저 수정했습니다"를 보여준다. 입력한 내용은 유지된다.

## 4.6 삭제

- 상세 화면에서 삭제하며, 한 번 더 확인을 받는다.
- 삭제하면 복구할 수 없고, 렌더링 URL도 더 이상 열리지 않는다.

# 5. 렌더링

## 5.1 동작

- 렌더링은 항상 **새 창(새 탭)**에서 열린다. 관리 화면 안에 끼워 보여주지 않는다.
- 렌더링 화면은 관리 화면과 **다른 주소**를 쓴다. 예: 관리 `render-box-admin.<계정>.workers.dev`, 렌더링 `render-box-render.<계정>.workers.dev`
- 업로드된 HTML의 코드가 관리 화면이나 로그인 정보에 접근할 수 없도록 격리된다.

## 5.2 동작하는 것

AI가 만든 HTML에서 흔히 쓰는 것들은 그대로 동작한다.

- 외부 CDN의 스크립트·스타일 (Tailwind CDN, esm.sh, jsDelivr 등)
- 외부 폰트, 이미지, 지도·영상 임베드
- `alert`, `confirm`
- 화면 안에서만 처리하는 입력 폼
- 공개 API 호출
- 브라우저 저장소(`localStorage`). 단, 새로고침하면 초기화된다.

## 5.3 동작하지 않는 것 (등록 화면 안내 문구)

등록 화면에 다음 안내를 접을 수 있는 형태로 표시한다.

- 함께 있던 스크립트·스타일 파일은 올라가지 않습니다. 이미지는 저장할 때 파일을 선택하면 HTML 안에 넣어 줍니다.
- 브라우저 저장소(`localStorage` 등)는 새로고침하면 초기화됩니다.
- 새 창 열기(`window.open`, `target="_blank"`)와 파일 다운로드는 동작하지 않습니다.
- 외부 API는 모든 출처를 허용하는 공개 API(`Access-Control-Allow-Origin: *`)만 호출할 수 있습니다.
- 주소를 바꾸는 페이지 이동 방식(`history.pushState`)을 쓰면 새로고침 시 문서를 찾지 못합니다. 해시(`#/page`) 방식을 권장합니다.

## 6.1 로그인

- 서비스 이름, 키 입력란, 로그인 버튼
- 안내: "키는 관리자에게 받으세요. 렌더링 화면은 키를 묻지 않습니다."

## 6.2 목록

- 상단: 검색창, [새 HTML 등록] (EDITOR만), 키 관련 안전 안내
- 표: 제목, 설명, 링크 개수, 크기, 수정자, 수정일, [↗ 새 창]
- 행을 클릭하면 상세로 이동
- 삭제 직후에는 "삭제했습니다" 표시

## 6.3 등록

- 파일 드롭 영역 (또는 [파일 선택])
- [직접 붙여넣기]로 전환하면 텍스트 영역 표시
- 제목 (자동 채움), 설명
- 링크 목록: 이름·URL 입력 행, [+ 링크 추가], 행별 [삭제] (최대 10개)
- 이미지 파일 연결 영역 (4.2, 필요할 때만 표시)
- 경고 영역 (4.2)
- 렌더링 환경 안내 (5.3, 접을 수 있음)
- [저장] [취소]

## 6.4 상세

- 4.4 참고
- 저장 직후에는 "저장했습니다"를 표시하고 [렌더링 URL 복사]를 강조한다.

## 6.5 수정

- 문서 정보 입력(제목, 설명, 링크)
- HTML 교체 영역 (등록 화면과 같은 파일·붙여넣기 방식, 비워 두면 유지)
- 현재 HTML 크기와 마지막 수정자 표시

## 6.6 렌더링

- 업로드된 HTML을 그대로 보여준다.
- MVP 2에서 화면 구석에 플로팅 툴바를 추가한다.

# 7. MVP 1 완료 기준

- [ ] 운영자가 EDITOR·VIEWER 키를 발급·회수하고 역할을 변경할 수 있다.
- [ ] 키를 한 번 입력하면 관리·렌더링 모두 로그인되고 30일간 유지된다.
- [ ] 회수된 키는 즉시 모든 화면에서 차단된다.
- [ ] EDITOR가 파일 드래그 또는 붙여넣기로 HTML을 등록할 수 있다.
- [ ] 제목·설명과 함께 링크를 여러 개(최대 10개) 등록·수정할 수 있고, 상세에서 링크를 열 수 있다.
- [ ] EUC-KR 파일이 깨지지 않고 등록된다.
- [ ] 같은 폴더의 이미지를 쓰는 HTML에 이미지 파일을 넣으면 HTML 안에 포함되어 표시되고, 넣지 않은 이미지는 빈 상자로 표시된다.
- [ ] 같은 폴더 스크립트·스타일 참조와 `http://` 리소스에 대한 경고가 표시된다.
- [ ] 최대 크기(실측 후 확정, 목표 10MB) 이하의 HTML(한글 위주 포함)을 등록하고 렌더링할 수 있다.
- [ ] 목록 검색과 페이지 이동이 동작한다.
- [ ] 상세에서 렌더링 URL 복사, 소스 보기, 소스 다운로드가 동작한다.
- [ ] 정보 수정, HTML 교체, 삭제가 동작하고, 정보만 수정하면 HTML이 그대로 유지된다.
- [ ] 동시에 수정하면 나중에 저장한 사람에게 안내가 나오고 덮어쓰지 않는다.
- [ ] 메신저로 받은 렌더링 URL을 클릭하면 (최초 로그인 후) 새 창에서 문서가 열린다.
- [ ] AI 생성 HTML의 일반 패턴(Tailwind CDN, 외부 폰트·스크립트, `alert`, 화면 안 입력 폼)이 동작한다.
- [ ] VIEWER는 등록·수정·삭제를 할 수 없다 (서버에서 차단).
- [ ] 기술 검증 항목([design.md](design.md) 10장 CI 필수 테스트, 브라우저 점검, 배포 후 점검)을 통과한다.

# 8. 제품 원칙

1. 기획자가 파일 하나만 올리면 개발자가 URL 하나로 본다. 이 흐름을 방해하는 기능은 넣지 않는다.
2. 올라온 HTML은 고치지 않고 그대로 실행한다. 대신 안전하게 격리한다.
3. 소수 사용자용 내부 도구에 맞게 단순하게 만든다. 필요가 확인된 기능만 다음 단계에 추가한다.
